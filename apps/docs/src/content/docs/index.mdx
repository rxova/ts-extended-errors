## What it gives you

<CardGrid>
  <Card title="Subclasses that work" icon="approve-check">
    `name` is the class name, `instanceof` holds after downlevel compilation, and the stack starts
    at the throw site rather than inside the constructor.
  </Card>
  <Card title="A code and a context" icon="seti:typescript">
    A stable string per class to branch on, and a typed data object per error, so failure details
    stop being interpolated into prose and parsed back out.
  </Card>
  <Card title="One-line classes" icon="puzzle">
    `defineError('NotFoundError', { base: HttpError, code: 'HTTP_NOT_FOUND' })` builds a real
    class, and `base` builds families of them.
  </Card>
  <Card title="Cause chains you can search" icon="magnifier">
    A low-level failure is usually wrapped two or three times before it reaches the handler that
    knows what to do about it. `findCauseOf` finds it at any depth.
  </Card>
  <Card title="A JSON round trip" icon="seti:json">
    `serializeError` produces a plain object; `deserializeError` rebuilds it as the classes it was,
    so `instanceof` still works on the other side of a queue or an HTTP response.
  </Card>
  <Card title="Tolerance for anything thrown" icon="warning">
    Every function takes `unknown`, including strings, plain objects and `null`. No runtime
    dependencies and no Node APIs, so it runs in browsers and workers too.
  </Card>
</CardGrid>

## In one example

```ts
import { defineError, findCauseOf, serializeError, toError } from 'ts-extended-errors'

const HttpError = defineError('HttpError', { code: 'HTTP' })
const NotFoundError = defineError('NotFoundError', { base: HttpError, code: 'HTTP_NOT_FOUND' })

function loadProfile(userId: number) {
  try {
    throw new NotFoundError('no such user', { context: { userId } })
  } catch (cause) {
    throw new HttpError('loading the profile failed', { cause })
  }
}

try {
  loadProfile(42)
} catch (thrown) {
  const error = toError(thrown) // `thrown` is `unknown`; `error` is an `Error`

  // Searches the whole cause chain, not just the outermost error.
  const notFound = findCauseOf(error, NotFoundError)
  notFound?.code // 'HTTP_NOT_FOUND'
  notFound?.context // { userId: 42 }

  console.log(JSON.stringify(serializeError(error, { includeStack: false })))
  // {"name":"HttpError","message":"loading the profile failed","code":"HTTP","cause":
  //   {"name":"NotFoundError","message":"no such user","code":"HTTP_NOT_FOUND",
  //    "context":{"userId":42}}}
}
```
